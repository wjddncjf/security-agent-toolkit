# 2026-11-16 학습 기록

## 1. 학습 주제
- Network-014: 정규표현식과 탐지 룰
- 비정형 로그 분석 및 정규화
- 계정별 로그인 실패 횟수 집계와 탐지 룰 작성

## 2. 실습 내용
- `split()`으로 로그를 나누고 `parts[6]`을 출력해 계정 이름을 확인했다.
- 로그에 `invalid user`가 추가된 경우 실제 계정인 `guest` 대신 `invalid`가 출력되는 문제를 확인했다.
- `len()`으로 로그마다 값의 개수가 다른 것을 비교하고, `parts[-1]`로 마지막 값을 추출하는 방법을 실습했다.
- `raw_logs.txt` 전체 20줄에서 6번 인덱스를 출력한 결과, 계정 이름 외에도 `10.1.2.34`, `invalid` 등의 값이 섞여 나오는 것을 확인했다.
- `re.search()`와 `re.findall()`을 사용해 로그에서 IP와 계정을 검색하는 코드를 작성했다.
- 네임드 그룹과 `groupdict()`를 활용해 시간, 등급, 계정, IP를 딕셔너리 형태로 추출했다.
- 정규화된 로그를 JSON으로 저장하고, `WARN` 기록을 계정별로 집계하는 코드를 작성했다.
- 로그인 실패 횟수가 임계값 이상인 계정을 찾아 경보를 출력하는 탐지 룰을 작성했다.

## 3. 막힌 부분 및 해결
- `assignment_14_f2.py` 실행 중 `FileNotFoundError`가 발생했다.
- Python 파일과 `raw_logs.txt`가 모두 `agent_core`에 있었지만, 터미널의 작업 위치가 상위 폴더인 `security-agent-toolkit`으로 설정되어 있었다.
- `cd ~/security-agent-toolkit/agent_core`로 작업 위치를 변경해 파일 경로 문제를 해결했다.
- Python 파일의 위치와 상대경로로 파일을 읽을 때 기준이 되는 현재 작업 위치가 다를 수 있다는 점을 확인했다.

## 4. 새롭게 알게 된 점
- `split()`으로 고정된 위치의 값을 추출하면 로그 형식이 달라졌을 때 오류 없이 잘못된 값이 나올 수 있다.
- 정규표현식은 문자열의 위치보다 특정 문자 패턴을 기준으로 값을 추출할 수 있다.
- `re.search()`는 일치 결과가 없으면 `None`, `re.findall()`은 빈 리스트를 반환한다.
- 네임드 그룹을 이용하면 여러 값을 이름으로 구분하고 딕셔너리로 변환할 수 있다.
- 탐지 룰의 임계값은 고정된 정답이 아니라 정상적인 사용 패턴과 탐지 목적을 고려해 정해야 한다.
