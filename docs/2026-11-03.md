# 1. 왜 이걸 하는지 찾아봅니다.
git 으로 올릴 때는 왜 add · commit · push 세 단계로 나눌까요 :

git add : 어떤 파일을 저장할지 고른다.
git commit : 선택한 파일의 변경사항을 로컬 저장소에 기록한다. 작업 내용을 하나의 기록으로 남긴다
git push : 로컬 저장소의 커밋을 원격 저장소로 전송한다. Github에 기록 올리기.

파일을 수정했다고 하여 모든 변경 사항을 Github에 올려야 하는 것은 아니 때문에 사용자가 원하는 변경 사항만 선택하고 관리하여 업로드 할 수 있다.

## 2. 이 말들이 무슨 뜻인지 찾아봅니다.
commit(커밋) : 파일의 변경 사항을 Git의 로컬 저장소에 하나의 기록으로 남기는 것이다. 
왜 메시지를 함께 남길까?
나중에 Git 기록을 확인했을 때 언제, 어떤 작업을 했는지 쉽게 파악하기 위함이다.

push(푸시) : 내 컴퓨터의 로컬 저장소에 기록한 커밋을 GitHub 같은 원격 저장소로 전송하는 것이다.

# 두 개념 스스로 찾아보기.
중첩(nested) : 중첩이란 하나의 데이터 안에 또 다른 리스트나 딕셔너리 등의 데이터 구조가 들어 있는 것을 의미한다.
딕셔너리 안의 닥셔너리 : 딕셔너리 안의 딕셔너리는 특정 키를 기준으로 관련 정보를 구분하고 조회할 때 사용한다. 리스트 안의 딕셔너리는 여러 개의 데이터를 하나의 목록으로 관리하거나 반복문으로 처리할 때 사용한다. 따라서 특정 대상을 키로 빠르게 찾고 싶다면 딕셔너리 안의 딕셔너리를, 여러 항목을 순서대로 저장하고 처리하려면 리스트 안의 딕셔너리를 사용하는 것이 적합하다.

# JSON 개념 스스로 찾아보기.
JSON: JSON은 서로 다른 프로그램이 데이터를 주고받을 수 있도록 정해진 표준 텍스트 형식이다. 프로그래밍 언어마다 데이터를 표현하는 방식이 다르기 때문에 공통된 규칙이 필요하다. JSON은 구조가 단순하고 사람이 읽기 쉬우며 다양한 프로그래밍 언어에서 사용할 수 있어 데이터 교환에 널리 사용된다.

직렬화(serialize): 직렬화란 프로그램의 메모리에 저장된 데이터 구조를 파일에 저장하거나 다른 프로그램으로 전송할 수 있는 형태로 변환하는 과정이다. 메모리 속 값을 글자로 편다는 것은 딕셔너리나 리스트 같은 데이터를 JSON과 같이 정해진 규칙을 가진 문자열로 표현한다는 의미이다. 이를 통해 데이터를 저장하거나 서로 다른 프로그램 간에 주고받을 수 있다.

### 2. 찾아보고 알게 된 것

**add와 commit과 push의 차이**

- git add: 변경한 파일 중 커밋할 파일을 선택한다.
- git commit: 선택한 파일의 변경 사항을 로컬 저장소에 기록한다. 커밋 메시지를 통해 어떤 작업을 했는지 확인할 수 있다.
- git push: 로컬 저장소에 기록한 커밋을 GitHub 원격 저장소로 전송한다.

세 단계로 나누는 이유는 필요한 변경 사항만 선택하고, 작업 이력을 기록한 뒤 GitHub에 업로드하기 위해서이다.

**untracked · tracked · staged**

- untracked: Git이 아직 추적하지 않는 새 파일이다.
- tracked: Git이 추적하고 있는 파일이다.
- staged: git add를 통해 다음 커밋에 포함하도록 선택한 변경 사항이다.

## Network-008 · 딕셔너리와 JSON 실습

### 1. 학습 내용

#### 1.1 딕셔너리(Dictionary)
- 키(Key)와 값(Value)을 이용해 데이터를 저장하는 자료구조
- 리스트는 인덱스로 값을 조회하지만, 딕셔너리는 키를 이용해 값을 조회
- 기존 키에 값을 할당하면 값이 수정되고, 새로운 키에 값을 할당하면 항목이 추가됨

#### 1.2 get()과 in
- 존재하지 않는 키를 대괄호로 조회하면 KeyError가 발생함
- get()을 사용하면 존재하지 않는 키를 조회해도 오류 없이 None을 반환함
- get('ip', '알 수 없음')처럼 기본값을 지정할 수 있음
- in을 사용하면 특정 키의 존재 여부를 True 또는 False로 확인할 수 있음

#### 1.3 중첩 자료구조
- 리스트 안의 딕셔너리: 여러 데이터를 목록 형태로 관리
- 딕셔너리 안의 딕셔너리: 특정 키를 기준으로 관련 정보를 관리
- 인덱스와 키를 함께 사용해 중첩된 데이터에 접근할 수 있음

#### 1.4 JSON 데이터 처리
- json.dumps(): Python 데이터를 JSON 문자열로 변환
- json.loads(): JSON 문자열을 Python 데이터로 복원
- json.dump(): Python 데이터를 JSON 파일에 저장
- json.load(): JSON 파일을 읽어 Python 데이터로 복원

### 2. 실습 내용

#### 2.1 F1 · 이름으로 값 찾기

#### 2.2 F2 · JSON 저장과 복원

파일: `agent_core/assignment_08_f2.py`

**실습 목적**
- 리스트 안의 딕셔너리를 JSON 파일로 저장하고 다시 읽어 값을 조회한다.

**작성한 코드**

    import json

    logs = [
        {'user': 'kim01', 'count': 4},
        {'user': 'lee02', 'count': 1}
    ]

    with open('logs.json', 'w', encoding='utf-8') as f:
        json.dump(logs, f, ensure_ascii=False, indent=2)

    with open('logs.json', 'r', encoding='utf-8') as f:
        back = json.load(f)

    print(back[0]['user'])

**출력 결과**

    kim01

**학습 내용**
- json.dump()를 이용해 logs.json 파일 저장
- json.load()를 이용해 JSON 파일의 데이터 복원
- back[0]으로 리스트의 첫 번째 딕셔너리에 접근
- ['user']를 이용해 첫 번째 사용자의 이름 조회

### 3. 오류 및 새롭게 알게 된 점
