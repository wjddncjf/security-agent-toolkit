# 1. 왜 이걸 하는지 찾아봅니다.
git 으로 올릴 때는 왜 add · commit · push 세 단계로 나눌까요 :

git add : 어떤 파일을 저장할지 고른다.
git commit : 선택한 파일의 변경사항을 로컬 저장소에 기록한다. 작업 내용을 하나의 기록으로 남긴다
git push : 로컬 저장소의 커밋을 원격 저장소로 전송한다. Github에 기록 올리기.

파일을 수정했다고 하여 모든 변경 사항을 Github에 올려야 하는 것은 아니 때문에 사용자가 원하는 변경 사항만 선택하고 관리하여 업로드 할 수 있다.

## 2. 이 말들이 무슨 뜻인지 찾아봅니다.
commit(커밋) : 파일의 변경 사항을 Git의 로컬 저장소에 하나의 기록으로 남기는 것이다. 
왜 메시지를 함께 남길까?
나중에 Git 기록을 확인했을 때 언제, 어떤 작업을 했는지 쉽게 파악하기 위함이다.

push(푸시) : 내 컴퓨터의 로컬 저장소에 기록한 커밋을 GitHub 같은 원격 저장소로 전송하는 것이다.

### 2. 찾아보고 알게 된 것

**add와 commit과 push의 차이**

- git add: 변경한 파일 중 커밋할 파일을 선택한다.
- git commit: 선택한 파일의 변경 사항을 로컬 저장소에 기록한다. 커밋 메시지를 통해 어떤 작업을 했는지 확인할 수 있다.
- git push: 로컬 저장소에 기록한 커밋을 GitHub 원격 저장소로 전송한다.

세 단계로 나누는 이유는 필요한 변경 사항만 선택하고, 작업 이력을 기록한 뒤 GitHub에 업로드하기 위해서이다.

**untracked · tracked · staged**

- untracked: Git이 아직 추적하지 않는 새 파일이다.
- tracked: Git이 추적하고 있는 파일이다.
- staged: git add를 통해 다음 커밋에 포함하도록 선택한 변경 사항이다.
